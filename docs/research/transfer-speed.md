# Where to look for transfer speed

Two phones completed a file over 4 GB at a reported **0.73 MB/s** (5.84 Mbit/s if decimal). Route, band, signal, raw throughput and storage timings were unrecorded. In the existing 100 MB emulator baseline, waiting for HTTP response headers consumed 138.9 of 257.5 seconds. That makes repeated range requests the first hypothesis to test on phones. [Benchmark measurements](../BENCHMARKS.md)

## What the reference implementations establish

Apple documents BLE announcements to nearby awake devices, direct peer-to-peer Wi-Fi and TLS. Researchers observed AWDL and an HTTPS upload in the AirDrop version they studied. Apple publishes neither a current HTTP wire contract nor an Android AWDL API. The transferable idea is to negotiate on a low-power channel and stream on a separately authenticated fast link. [Apple Platform Security](https://support.apple.com/guide/security/sec2261183f4/web) · [Original protocol measurements, figure 3](https://www.usenix.org/system/files/sec19-stute.pdf)

Google's public Nearby Connections protocol exchanges supported media and attempts a higher-bandwidth connection. Its code filters candidates using capabilities and policy. Bluetooth Classic, BLE, Wi-Fi LAN, hotspot, Direct and Aware appear in the design. What's usable depends on platform and build. The public SDK exposes bytes (up to 32 KB), files (minimal copying across process boundaries), and streams of unknown size. Google doesn't document a fixed fallback order, frame size or guaranteed throughput for a particular Quick Share handset release. [Connections overview](https://developers.google.com/nearby/connections/overview) · [Protocol and platform matrix](https://github.com/google/nearby/blob/main/connections/README.md) · [Medium selection](https://github.com/google/nearby/blob/main/connections/implementation/base_pcp_handler.cc)

## Android decisions

| Option | Decision and device limits |
|---|---|
| Existing LAN | Measure it first. Record both phones' band and link rate where available. Compute efficiency against a memory-to-memory TCP run on the same route, direction and screen state. Repeat with pinned TLS to isolate its cost. |
| Wi-Fi Direct | API 29 introduced creating or joining a group using a known network name and passphrase and requesting 5 GHz. Exchange credentials over the paired control path. Check hardware support and handle group creation failure. A requested band gives no private airtime or speed guarantee. [Android 10 Wi-Fi APIs](https://developer.android.com/about/versions/10/features) · [P2P configuration](https://developer.android.com/reference/android/net/wifi/p2p/WifiP2pConfig.Builder) |
| LocalOnlyHotspot and WifiNetworkSpecifier | Keep the host reservation alive. The guest requests the exact network and handles the system chooser, denial and timeout. This network provides local access. Concurrent internet Wi-Fi depends on device support. Release the request and reservation when finished. Android controls subsequent association. [Hosting](https://developer.android.com/develop/connectivity/wifi/localonlyhotspot) · [Joining](https://developer.android.com/develop/connectivity/wifi/wifi-bootstrap) |
| Wi-Fi Aware | Check feature support and current availability on both phones. Establish discovery sessions and request a peer data path. Availability can change during hotspot or Direct use. Compare setup time as well as sustained speed. [Wi-Fi Aware](https://developer.android.com/develop/connectivity/wifi/wifi-aware) |
| Routing and fallback | Use the selected Network's socket factory or bind each unconnected data socket before connect. Preserve the paired TLS identity and durable offset when switching paths. On failure, resume over the reachable LAN or hotspot. [Android Network](https://developer.android.com/reference/android/net/Network) |
| Screen off | On Android 10–13 a supported high-performance lock can remain effective on an AP with the screen off. Android 14+ maps it to low-latency mode, restricted to foreground, screen-on AP connections. Low-latency mode can reduce throughput. Measure both screen states even while the service holds its CPU lock. [Wi-Fi lock reference](https://developer.android.com/reference/android/net/wifi/WifiManager#WIFI_MODE_FULL_HIGH_PERF) |

Android 10–12 generally require fine location for nearby Wi-Fi discovery, and some discovery calls require Location services enabled. Android 12 introduced separate Bluetooth scan, advertise and connect permissions. On Android 13–15 with target 33+, the relevant P2P, hotspot and Aware calls require the nearby Wi-Fi runtime permission. Some scan APIs still need fine location. The project's minimum remains Android 11. [Wi-Fi permission guide](https://developer.android.com/develop/connectivity/wifi/wifi-permissions) · [Bluetooth permissions](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions)

## Optional Nearby experiment

The Android SDK requires available Google Play services on both phones. Transfers operate offline. Google documents usage analytics governed by the device's diagnostics preference. The public source is Apache 2.0. The distributed Android artifact separately declares the Android SDK license. [Android setup](https://developers.google.com/nearby/connections/android/get-started) · [Data collection](https://developers.google.com/nearby/connections/overview) · [Source license](https://github.com/google/nearby) · [Google Maven artifact metadata](https://dl.google.com/dl/android/maven2/com/google/android/gms/play-services-nearby/19.5.1/play-services-nearby-19.5.1.pom)

Evaluate FILE payloads only after measuring our pinned transport. Before accepting a file, both peers must prove possession of their existing pairing keys over a fresh transcript binding the Nearby session authentication token, both peer IDs, roles and nonces. Reject a mismatch or revoked identity. Verify file ID, length and SHA-256 against the authenticated offer. Compare setup, resume after interruption and end-to-end speed on the same phones. The choice of transport remains open until those results exist. [Nearby connection authentication](https://developers.google.com/nearby/connections/android/manage-connections)
